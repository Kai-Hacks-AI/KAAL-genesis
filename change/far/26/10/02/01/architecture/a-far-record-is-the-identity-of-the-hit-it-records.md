id: a-far-record-is-the-identity-of-the-hit-it-records
---

A FAR record is the identity of the Hit it records, and the Runs it admits state it.

FAR walks the accepted states of main in order, one record to a Hit, so a record has no need of a name taken from where Git or GitHub keeps that state: the record's own identity, its Change occurrence `far/YY/MM/DD/CC`, is the identity of the Hit it is about. That identity is opaque to Testing, which retains it with a Run and never reads it. A Run FAR admits states it as its candidate identity, and the admission is FAR's to judge, the one fact Testing does not: every admitted Run states the identity of the record that holds it, and the Runs together show the record's Plan, which Testing's evidence computes from them. The Plan and each Run are kept in the record and sealed with it, once, after they are made, because the state they tested is the Hit, which no record writes. Each Run says where it executed only as a placeholder, as FAR's earlier Runs do, so the record keeps no location, provider, workflow, artifact or commit. A Git boundary realizes the identity as a commit and shows that the workspace a Run executed is that commit; that mapping is that boundary's, never read from the record, and a record read with no Git, GitHub or original host still says which Hit it is about, what it requires of it and what Runs showed it.
