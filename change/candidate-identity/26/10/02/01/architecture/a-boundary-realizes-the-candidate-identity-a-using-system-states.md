A using system states a candidate identity, a boundary realizes it as a workspace and shows that the workspace is it, and Testing executes in the workspace and keeps the identity.

The relation is the one between a need stated in KAAL's terms and an adapter that realizes it, as for an environment. The using system owns what the identity is for: FAR owns the relation between a Hit and the identity the evidence it requires must concern. A Git boundary owns every fact that is true only of Git: reconstructing the state at a commit, materializing the workspace, and showing that the workspace is that commit, including the line-ending conversion a checkout applies. A hosting boundary owns jobs, hosts and the artifacts that carry a report. None of that enters Testing, and a Requirement, Test Case, Plan or Run takes no meaning from a commit. No Git boundary exists yet: today a provider-side step checks that every host checked out one commit, outside the report. This record places that responsibility and builds nothing.
