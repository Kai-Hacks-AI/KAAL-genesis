---
idea: KAAL can become modular through packages whose dependencies close the
  selected capability composition
---

The possible architecture is:

1. selected KAAL packages;
2. the package dependency graph;
3. transitive capability composition;
4. the active understanding for that composition;
5. Genesis;
6. a new modular KAAL.

Package dependencies could provide the dependency mechanism. KAAL should not invent a dependency resolver if the package layer already supplies one. The mechanism supplied by packages is distinct from KAAL's meaning: capability meaning remains in KAAL and BRAIN.

Genesis could eventually birth the active understanding of the selected composition. A newborn would inherit that active understanding, not replay superseded historical BRAIN nodes. Learning accumulates history; birth inherits active understanding.

This record retains the architectural possibility. It does not commit KAAL to packaging, dependency resolution, a modular Genesis, or implementing this architecture now.
