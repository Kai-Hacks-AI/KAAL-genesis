# Using Skills

A skill is a directory holding `SKILL.md`: YAML frontmatter, then the instructions an agent follows. This skill checks skills against the Agent Skills standard (https://agentskills.io/specification) and against one engineering rule: a skill is born from its own init.

The standard: the frontmatter's `name` is required, 1 to 64 lowercase letters and digits of any script and single hyphens, not starting or ending with a hyphen, and equal to the skill's directory name; like the standard's reference validator, `skills-ref`, names are compared in Unicode NFKC form. `description` is required, 1 to 1024 characters, saying what the skill does and when to use it. `license` (a string), `compatibility` (1 to 500 characters), `metadata` (strings to strings) and `allowed-tools` (a space-separated string) are optional, and no other field is allowed. `scripts/`, `references/` and `assets/` hold what the instructions use.

Born from init: running the skill's `scripts/init.ts` (`tsx scripts/init.ts`) writes the skill's `SKILL.md` next to the scripts. `SKILL.md` is never edited by hand: change init and run it. Init is self-contained: it uses only Node's built-in modules and its own skill's files, and finishes within a minute. A skill is born correctly when its committed `SKILL.md` is exactly the bytes its init generates, so the using system must keep `SKILL.md` byte-exact wherever it is checked out and never reformat it.

Collecting: a skill that manages durable things, such as Requirements, lets a caller obtain them from a scope without knowing how they are kept: the skill that owns a thing owns how it is recognized, read, validated and collected, and the caller owns why it asks. Such a skill declares it by having `scripts/collect.ts`, run as `tsx scripts/collect.ts <scope>...` where each scope is a directory: it prints the things found in the scopes as a JSON array and exits 0, or, when something claims to be one and is not, says why on stderr, prints nothing on stdout and exits 1. A scope holding nothing yields `[]`, which is the whole of what checking requires, since what a thing is belongs to its skill. Collection is local, never an accidental traversal: it finds what lies directly in each scope given, and a skill that must look deeper says so itself. This contract belongs only to skills that manage durable things. A skill with no such things, such as one that judges or runs, has no `scripts/collect.ts` and is never asked for one. Today the script is declared voluntarily: which skills ought to declare it is not machine-readable, and this skill infers nothing about what a skill manages from the scripts it happens to hold.

Check with `scripts/check.ts <skills-dir>`: every directory in it is a skill, and every way a skill breaks the standard, differs from what its init generates or, if it declares `scripts/collect.ts`, breaks the collecting contract is reported. Checking runs each skill's init with tsx in a scratch copy of the skill without its `SKILL.md`, never over the skill. It bounds a stuck init but is not a sandbox: init is the skill's own code, run as the caller, and a failed init is reported without its output, so run it to see why. A declared `scripts/collect.ts` is run the same way, from an empty scratch directory over an empty scope, never over the skill. Lengths count characters, not UTF-16 units. From code, `checkSkills` in `scripts/skills.ts` returns the same errors, and `standardErrors`, `birthErrors` and `collectErrors` check one skill against each rule. Which skills to keep and when to check them is the using system's decision; this skill only checks.
