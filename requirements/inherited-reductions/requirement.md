---
holds: KAAL names every piece of protection the accepted Regression Plan
  requires that a candidate's no longer does, from both states' own files, and
  nothing else
---

Given two states of KAAL's files, an accepted state and a candidate proposed to succeed it, KAAL names every reduction the candidate would make of what the accepted regression protects. What the accepted regression protects is what the accepted state's Regression Plan requires: each commitment it names, by its place, and each file a place it names by a wildcard covers; each check other than cases it says shows a commitment; each set of conditions it requires its testing shown under; and each suite that says it serves it. A reduction is any of those the candidate's Regression Plan no longer requires. A file a wildcard covers is a reduction of its own only while the candidate still names the wildcard. KAAL reads only the two states' own files, as directories, and asks neither Git nor GitHub which is which; what either state states through a link is refused, never read.

Nothing else is a reduction. What the candidate adds, and how it changes its code, its cases or their arrangement, reduces nothing its Regression Plan still requires.

A Requirement the accepted Regression Plan names that the candidate still names at the same place, but with a different record, is a loss that cannot be accepted: its inherited meaning would disappear at a place that seems to keep it.

Where this ends: which cases show a commitment, and how much of it, is not read here, so a case the candidate no longer keeps is not named as a reduction.
