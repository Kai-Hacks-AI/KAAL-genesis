# Genesis

Genesis launches KAAL into a repository that has none, as KAAL understands itself now. BRAIN remembers how KAAL learned; Genesis says how KAAL is born now.

Genesis births exactly what a new KAAL begins with, and nothing else: the root `AGENTS.md` and `brain/AGENTS.md`, byte for byte as KAAL keeps them, and one learning, `genesis/26/09/29/01`, holding KAAL's current understanding of the skills it uses and of how it works, in the nodes `using-brain`, `skill`, `using-skills`, `using-agents`, `using-seals`, `bass` and `testing`.

Each node Genesis births says only what KAAL's current node of that name says, and leaves out how KAAL came to it: that history stays in the BRAIN of the KAAL that learned it. Genesis is never behind KAAL: no node KAAL holds for a name Genesis births is newer than the learning Genesis births. Nothing a new KAAL is born with states KAAL's meaning through the operations of a system that keeps its files, such as a branch, a merge or a push, so a new KAAL works without one.

A new KAAL is not born with the commitments of the KAAL that launched it, such as this one: they are about launching KAAL, and a new KAAL begins with what it needs to work. Nor is it born with a regression: the first regression a KAAL accepts has no regression before it to be derived from.

This node supersedes the earlier one only in the learning Genesis births: KAAL's testing node is now newer than that learning, and Genesis is never behind KAAL.
