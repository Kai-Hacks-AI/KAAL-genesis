# HAPTIC

KAAL reads control along HAPTIC:

`Human < Agent < Program`, To Improve Control

HAPTIC ranks who controls an operation: who decides that it runs and what follows from its result. Left to right, that control becomes more deterministic: a human controls by interpretive judgment, an agent by leveraged reasoning, a program by deterministic execution with neither in the loop. Moving control right improves it only when understanding has earned deterministic encoding. Encoding control that is not yet understood does not remove wrongness; it makes the wrongness deterministic.

HAPTIC and BASS are orthogonal axes that meet at Agent, like a crossword:

```
            Bare
             |
Human ---- Agent ---- Program
             |
           Skill
             |
           Script
```

BASS ranks the capability an agent works with; HAPTIC ranks who controls. The same capability can sit under different control: one script is at Agent when an agent decides to run it and acts on its result, and at Program when a program does, such as a check that runs on every candidate. A script is a capability, not a position in HAPTIC. BASS describes only an agent's capabilities, so the axes cross only at Agent. The shared words and the shared direction toward determinism are real, but BASS is capability maturity and HAPTIC is control delegation.

HAPTIC is KAAL's understanding, not a mechanism: it defines no control levels, routing or permissions.
