# Testing

KAAL uses the **testing** skill because Genesis showed that its testing had outgrown Bare.

KAAL tested Genesis without a testing capability of its own. That Bare Testing was repeated often enough to show its own structure: tests stated claims, test data was kept apart from test cases, tests ran repeatedly on every platform KAAL supports, and failures found by review and probing became test cases, or, when they kept recurring, changed the mechanism instead. That structure is the evidence for moving forward in BASS, from Bare to Skill.

The skill holds only what that evidence justifies. KAAL has not yet formalized how its tests are run, grouped or planned; that understanding is expected to grow backwards from the tests KAAL already has, and the skill to grow with it.

The skill explains how a test is written. This node records why KAAL uses it.
