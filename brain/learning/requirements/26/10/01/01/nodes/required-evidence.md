A Requirement states what must hold and never what shows it, a Test Case is generic HOW that carries no environment, and Testing compares a parameter only by equality with what a Run observed. The relation "this Requirement must be evidenced under these parameters" is therefore none of theirs: it is KAAL's, composed from accepted material. A Change keeps it as a decision in its occurrence's evidence/ directory, one Markdown file naming a Requirement, the parameters and why, so the Requirement stays as sealed and no Test Case is copied per environment. linux-support and windows-support are decided by the Change execution-environments/26/10/01/02 under the parameter platform, the name and value a Run already observes (linux, and win32 which is how Node spells Windows), so no adapter has to supply a condition for them. KAAL derives from those decisions, the Test Cases that test each Requirement and what supersedes them, the instances a Plan requires: a Test Case under each set of parameters of the Requirement it is selected for, under none for a Defect or a Requirement no decision names, so git-independence and github-independence still require their HOW and nothing more. Not decided: how a Run under a parameter is provided, or combining Runs in CI; no Run is made by deriving instances.
